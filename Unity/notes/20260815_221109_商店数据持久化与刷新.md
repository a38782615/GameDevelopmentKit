# 商店数据持久化与刷新总结

## 完成内容

- `ShopItemData` 接入现有 Archive 存档系统，游戏数据加载和全量保存流程均包含商店数据。
- 商品购买成功后同步保存剩余购买次数。
- 新增 `GameDataMgrComponent.RefreshShopData()`，按当前 `DTItems` 重建商品并恢复默认购买次数。
- 商店数据使用 `ConfigId` 作为稳定存档 ID；加载时保留已有次数、补齐新增配置，并迁移和清理旧的随机 ID、重复记录及失效配置。
- 重复旧记录迁移时优先采用稳定 ID；没有稳定记录时采用最小剩余次数，避免恢复已经消费的购买次数。
- 刷新和迁移均先完成稳定记录写入，再删除废弃记录，降低中途失败导致数据丢失的风险。
- 玩家灵石、背包物品和商品次数通过同一个 LiteDB 事务保存；事务失败时使用购买前快照同步回滚内存变更，不受选中项或配置热更影响。
